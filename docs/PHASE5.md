# Phase 5: アプリ(Curstyle.app)

Phase 5 は2段に分ける。5a はアプリ本体・一覧とプレビュー・適用と復元・メニューバー・Windows 取り込み・診断・ヘルパーの SMAppService 化。5b は hotspot / フレーム速度の編集と .cape / GIF の取り込み。

## 5a の仕様

### 組み立てと置き場所

- `./make-app.sh` で `.build/Curstyle.app` を組み立て、`~/Applications/Curstyle.app` に置く(ad-hoc 署名)。~/Desktop などの保護フォルダに置くと、launchd から起動したヘルパーが TCC の確認待ちで止まるため。
- バンドルの中身:
  - `Contents/MacOS/CurstyleApp`: SwiftUI のアプリ本体(ターゲット名を `Curstyle` にしないのは、大文字小文字を区別しないファイルシステムで `curstyle` と衝突するため)
  - `Contents/MacOS/curstyle`: CLI。ヘルパーの実体も兼ねる
  - `Contents/Library/LaunchAgents/io.github.narcissus-tazetta.curstyle.helper.plist`: SMAppService で登録するヘルパー(`BundleProgram` = `Contents/MacOS/curstyle`、引数 `helper run`)
- `LSUIElement` で起動し、ウィンドウを開いている間だけ Dock に出す。ウィンドウを閉じてもメニューバーに残る。

### テーマのライブラリ

- `~/Library/Application Support/Curstyle/themes/<UUID>/theme.json`(`ThemeLibrary`)。書き出し途中のものが一覧に出ないよう、隠しの一時名で書いてから rename する。
- 削除はゴミ箱へ移す。適用中のテーマを消しても、自動再適用は `active-theme/` の写しを使うので壊れない。
- 「適用中」の判定は、テーマの中身の指紋(キーと各カーソルの contentHash。名前は含めない)を `active-theme/` と比べて行う。CLI で適用したテーマでも、同じ中身ならライブラリ側で適用中と表示される。

### 取り込み

- 入口: サイドバーの「＋」(⌘O)、ウィンドウへのドラッグ＆ドロップ、Dock アイコンへのドロップ / `open -a Curstyle <フォルダ>`。
- `theme.json` があれば Curstyle のテーマとして読む。無ければ Windows のカーソルフォルダとして読む。直下に .ani / .cur が無ければ1階層下を探し、アニメ版(.ani を含むフォルダ)を優先する。1つに決まらなければ取り込まない(利用者がフォルダを選び直す)。
- 取り込む前にシートで、役割ごとのプレビュー・取り込まないファイル・大きさ(既定は 1 px = 1 pt)を見せる。適用時と同じ検証(`resolvedPlan`)を取り込み時に通す。

### 画面

- サイドバー型(`NavigationSplitView`)。「テーマ」(ライブラリ)を一覧し、下端に設定への入口・適用中のテーマと自動再適用の状態・標準に戻すボタンを固定する。
- テーマ詳細: 見出しのカード(代表カーソルの大きなプレビュー・名前の変更・適用中 / アニメ / 種類数 / 大きさ・適用 / 標準に戻す)と、役割ごとのカードのグリッド(基本・ドラッグ・サイズ変更・その他)。アニメは登録形式どおりの間隔で再生し、「視差効果を減らす」では先頭フレームで止める。ツールバーで背景(明るい / 暗い / 市松)とホットスポットの表示を切り替える。
- 設定: 自動再適用ヘルパーのオン・オフ(SMAppService)、承認待ちのときはシステム設定を開く、停止中なら再開、アプリ本体のログイン項目、保存場所、復元、診断(`Diagnostics.run` の結果と不具合報告用レポートの書き出し。問題がない内訳とカーソル名ごとの行は折りたたむ)。
- メニューバー: 状態の表示、テーマの切り替え、標準に戻す、ウィンドウを開く、終了。
- 操作の結果は上部のバナーで伝える(成功は数秒で消え、失敗は閉じるまで残る)。

### 適用・復元

- CLI と同じく、アプリのプロセスから `CursorEngine.apply` / `Recovery.restore` を呼ぶ(ロックも同じ)。終わったら `OverlayActivation.postChanged()` でヘルパーと他のプロセスに知らせる。overlay 方式で適用中なら、復元はジャーナルを clean にしてヘルパーに描画を止めさせる。
- CLI・ヘルパーからの変更は、同じ合図(distributed notification)とアプリが前面に来たときに読み直す。

### ヘルパーの移行

- ラベルは `curstyle helper install`(~/Library/LaunchAgents の旧方式)と同じ。両方が動くと再適用が二重になるので、アプリでオンにするときは旧方式を bootout して plist を消してから SMAppService で登録する。

## 5b の仕様

### .cape の取り込み

- plist の `Cursors` に識別子ごとの `FrameCount` / `FrameDuration` / `HotSpotX,Y`(pt)/ `PointsWide,High` / `Representations`(解像度ごとの画像データ。PNG か TIFF で、コマを縦に並べた1枚)を持つ形式。
- `Arrow` / `ArrowS` は `arrow`、`IBeam` / `IBeamS` は `ibeam`、`com.apple.cursor.N` は役割名(13 は `pointingHand`、`CursorCatalog.roleNames` に無い番号は `cursor.N`)のキーにする。Arrow と ArrowS の両方があれば S を使う。
- Move / Wait / Alias / Copy / ArrowCtx / IBeamXOR / Empty など、エンジンが差し替えない coregraphics の名前は取り込まない。検証に通らないカーソル、同じ登録先に当たる2つ目(cursor.7 と 8 など)も取り込まず、理由付きで取り込みシートに出す。
- 静止画の `FrameDuration`(1 が入っている)は 0 として扱う。
- 1x / 2x の画像がそのまま使えなければ(10倍の画像だけ、など)、最大の画像からコマごとに縮小して 1x と 2x を作る。

### 編集

- テーマ詳細のタイルを押すと編集シートが開く。保存するまでライブラリには書かない。
  - ホットスポット: プレビューのクリック・ドラッグ(0.5pt 刻み)か、数値とステッパー。
  - 1コマの秒数: アニメのときだけ。0.01〜2 秒。
  - 画像の差し替え: GIF(全コマ)か PNG(先頭の1枚)。長い辺を指定した pt(8〜128)にそろえ、1x と 2x を作る。GIF の表示時間が違うコマは最大公約数で等間隔にそろえ、25コマ以上になるものは拒否する。0.02 秒未満の表示時間はブラウザと同じく 0.1 秒として扱う。差し替え前のホットスポットは大きさの比で移す。
  - 同じ画像を使っているキー(Windows の Horizontal は6つのサイズ変更に当たる、など)は、既定で一緒に変える。
- 「…」メニューの「アニメの速さを一括で変える」で、全アニメの1コマの秒数を 0.5〜2倍の速さに変える。
- 保存はライブラリの別の場所に書いてから差し替える(作成日を引き継ぐので一覧の並びは変わらない)。
- アプリで最後に適用したテーマの ID を覚えておき、そのテーマが編集で適用中の中身と食い違ったら「適用中のものと内容が違います」と「変更を適用」を出す。保存しただけではカーソルを書き換えない。

## 実機で確かめたこと(2026-11-10、macOS 27.2 / arm64)

Phase 4 の常駐(CGS・miyabi-zzz)中のため、適用・復元・ヘルパーの切り替えはしていない。確かめたのは読み取りだけで済む範囲。

- `~/Applications/Curstyle.app` が起動し、ダーク・ライトの両方で崩れずに表示される。
- miyabi-zzz.cursor を Dock 経由で渡すと Cursors/(アニメ版)が選ばれ、26件・取り込まないファイル5件がプレビューされる。ライブラリに追加すると、CLI で適用中のテーマと同じ中身として「適用中」になる。
- テーマ詳細のアニメ再生、背景の切り替え、ホットスポットの表示。
- 取り込めないフォルダは、シートの中にエラーとして表示される。
- 起動と同時にフォルダを渡しても取り込みシートが開く(Static/ の .cur 版で確認。追加はしていない)。
- 診断画面の表示(問題なし。名前ごと26件は折りたたみ)。
- 操作の前後で、ジャーナル・active-theme・スナップショットの更新時刻は Phase 4 の開始時刻(09:06)のまま。

## 5b で実機で確かめたこと(2026-11-11)

Phase 4 の常駐中のため、適用はしていない(ジャーナル・active-theme・スナップショットの更新時刻は 09:06 のまま)。

- .cape 3件(GitHub で公開されているもの: 静止画 6件 TIFF、50pt・10倍 PNG だけ・24コマのアニメを含む 39件、I ビーム 2件 PNG)を `curstyle import` で取り込み、コマ数・ホットスポット・pt が plist の値と一致した。取り込み→書き出し→取り込み直しで中身が同じ。アプリの取り込みシートでもプレビューされ、取り込まない5件が理由付きで出た。
- GIF(miyabi の Gifs/、320px・12コマ・0.08 秒)から 32pt の 1x / 2x を作り、コマ数・間隔が ImageIO の値と一致、コマの絵も崩れていない。55コマの GIF は拒否された。
- 編集シート: プレビューのクリックでホットスポットが動く、数値・ステッパーで X / Y / 秒数が変わる、保存で theme.json の該当キーだけが変わる(画像とほかのキーは同じ)、GIF への差し替えと大きさの変更。
- 速さの一括変更: 2倍で 0.1 → 0.05 秒。
- 適用中のテーマ(miyabi-zzz)の矢印のホットスポットを (0,0) → (1.5,1)(剣の先)に変えると、「適用中のものと内容が違います」と「変更を適用」が出る。

## 確かめていないこと

- UI からの適用・復元、メニューバーからの切り替え(Phase 4 の常駐が終わる 2026-11-12 09:06 JST 以降)。
- SMAppService.agent が ad-hoc 署名のアプリから登録できるか、旧 LaunchAgent からの移行、登録したヘルパーでの再ログイン時の再適用。登録できなければ LaunchAgent を UI から入れる形に戻す。
- アプリを終了しても、アプリのプロセスから登録したカーソルが残るか(CLI では残る)。
- メニューバーの項目の見た目と操作(メニューバー右側が畳まれていて画面で確認できなかった)。
- 診断レポートの書き出し(保存パネルは別プロセスのため操作していない)、ゴミ箱への削除、名前の変更、ログイン項目のオン・オフ。
- Windows 取り込みの役割と番号の対応の目視。
- 5b: 編集したテーマ・.cape・GIF から作ったカーソルの適用(画面に出るか、ホットスポットどおりにクリックされるか)、「変更を適用」の動作。
- 5b: システムのライト表示での編集シート、同じ画像を使うキーの一括反映(Windows 由来のテーマで)。
